# An authoring agent drafts acceptance config builders; Azure is the oracle, not the agent

The acceptance-test **config builders** (`internal/native/services/<service>/<resource>_config.go`) are the largest zero-tooled hand-written surface per native resource: 200–370 LOC of `<Resource>Cfg` plumbing plus the Basic/Complete/Complete_update **Scenario** wrappers whose `Config()` methods render the HCL live-Azure acceptance tests apply. `_gen.go` (≈2289 LOC for storage) is generated and free; the azwise overlay is semi-tooled by the `azwise` agent; these builders had **no tooling at all**. Measured, "code gen is the expensive part" is false — the cost lives here and in azwise authoring.

**Decision.** Add an authoring agent + skill (`azapi-acceptance-author`) that drafts the whole `<resource>_config.go` in one shot. It is a **drafter, not a codegen and not a loop participant**:

- **Live acceptance stays live and human-run.** Acceptance exists to test real API behavior — round-trip, honored-vs-normalized, eventual consistency — which an offline plan cannot exercise. The agent is blocked from *running* acceptance (live Azure, minutes per apply) but not from *writing* it, so drafting is where its leverage is. We rejected any offline validation loop as the primary signal: it cannot test what acceptance is for.
- **Hybrid seed.** AzureRM's own `complete()`/`update()` acceptance configs already passed live Azure in AzureRM CI. Translating that proven HCL into azapin's ARM-body shape beats synthesizing property combinations from the schema alone — the schema-only path makes the agent *guess* valid combinations and burns a live-apply iteration per wrong guess. `update()` also reveals the proven in-place-updatable set that seeds Complete_update; azwise ForceNew flags say what to hold. When no AzureRM equivalent exists, the agent falls back to synthesis from schema + azwise defaults.
- **Best-guess + inline `TODO`, never silent omit — because Azure is the oracle.** This is the surprising, load-bearing choice. When a property cannot be confidently translated (no 1:1 automap path, a Dynamic-fallback subtree, a sub-service, a composite one-to-many join like `account_tier`+`account_replication_type` → `sku.name`), the agent emits its **best guess** with a `TODO(acceptance-author)` marker rather than dropping the property. The asymmetry is the whole argument: the human runs live apply regardless, so a wrong guessed value costs **exactly one** live-apply round-trip and Azure's named error points straight at the wrong `TODO`; **omitting** the property silently loses coverage and shoves the work back to hand-authoring. Maximize the draft, mark uncertainty inline, let Azure adjudicate. We rejected omit-and-report-uncertain (the safe-looking default): it minimizes wrong values but maximizes hand-authoring, the opposite of the bandwidth we are saving.
- **No agent correction loop.** After a failed apply the **human hand-fixes the flagged `TODO`** — the agent does not re-enter. Its entire value is a first draft good enough that corrections are a targeted punch-list, not a re-derivation. This keeps the human a pure oracle-runner and the agent a pure drafter, with no slow AI↔Azure round-trip.
- **Whole compiling file, not fragments.** The plumbing (`Cfg` struct, constructor, scenario type-wrappers, `RenderConfig` glue) is deterministic from the descriptor and free for the agent to emit, so it hands over something that compiles. `go build` on the service package is the static allowlist check — every drafted attribute must exist in the typed generated schema.

**Consequence.** The agent reuses existing mechanism, inventing nothing: `azwise_extract category=automap` already translates AzureRM snake_case fields to ARM body paths (its `unmapped` count *is* the `TODO` surface), and AzureRM sits at `../terraform-provider-azurerm` as the proven seed. It inherits a bounded translation hazard — a mis-guessed value costs one live-apply — deliberately, per the oracle argument. It inherits the codebase's **native-dependency wall**: when a scenario needs a dependency that has no native type, the agent fails loud and reports the missing ARM type instead of working around it with a foreign block, matching how the rest of native generation stops on the same wall. The two domain terms this rests on — **Acceptance config builder** and **Scenario** (Basic/Complete/Complete_update) — are pinned in `CONTEXT.md`. This sits beside `azwise` (overlay authoring) and `azapi-native-generator` (schema/overlay/hooks); it owns only the acceptance-config surface, and only the `_config.go` file — wiring scenarios into `Ordered` test containers stays human-owned.
